e-footprint · beginner's guide

Estimating your GenAI video workflow's footprint

A step-by-step guide for doing this for the first time — no coding or environmental-science background required.

01What we're trying to do together

You have a GenAI video workflow — maybe an AI drafts the prompt and a video model generates the clip, or something similar — and you'd like a rough sense of its environmental footprint: how much energy it uses and what that translates to in emissions.

We'll use e-footprint, an open-source modeling tool built for exactly this. You won't be writing any code yourself: you describe your workflow in plain language (or fill in a short spreadsheet), and an AI assistant does the technical work — building the model, running the numbers, and explaining the result back to you in plain language.

02Where to go

You need an AI assistant that can write and run Python code. Here's where to start.

Start here Whichever assistant you're reading this in

If you received this guide from an AI assistant, that same assistant can very likely do the whole thing for you — just go to one of the two routes below. No need to go anywhere else.

If you'd rather use something else, any assistant with code-writing and code-running ability will generally work, for example:

Claude (Anthropic)

Has a built-in ability to write and run Python, and to hand you back files.

ChatGPT (OpenAI)

Use a plan/mode with code execution enabled (sometimes called "Code Interpreter" or "Advanced Data Analysis").

One setting worth knowing about: if your assistant lets you pick a "thinking" or reasoning mode, or a more capable model tier, turn it on for this task. Building a multi-step model like this benefits from more careful, deliberate reasoning than a quick one-line answer — it's worth the extra moment.
Requirements, if you want to use a different assistant

Whatever you use needs to be able to:

  • Write and run Python code (not just talk about it) — this is how it will actually build the e-footprint model.
  • Install a Python package (efootprint) or otherwise access it.
  • Produce a file you can download (the JSON export).
  • Accept a file upload, if you're using Route A with the spreadsheet.

Assistants that are chat-only, with no code execution, won't be able to complete this on their own.

What about a European, open-weight option, like Mistral's Le Chat? Not for now. Le Chat does have a Code Interpreter that runs Python, but that sandbox has no internet access and doesn't come with efootprint preinstalled — so it can't install the library, and would either fail outright or improvise something that looks like a result but isn't really using e-footprint. We're not aware of another European or open-weight assistant that currently clears this bar either. Worth revisiting as these tools evolve.

03Two ways to get started

Both routes end up at the same place: a working model, a downloadable JSON file, and a plain-language summary. Pick whichever feels easier. You should have received three files alongside this guide - keep them in the same place:

e-footprint_video _input_template.xlsx — the spreadsheet (Route A)
prompt_A_with_spreadsheet.txt — the message to send for Route A
prompt_B_chat_only.txt — the message to send for Route B

Route A

Fill in the spreadsheet

Best if you already know roughly which models you're using and how often things run.

  1. Open e-footprint_video _input_template.xlsx and fill it in as best you can - it doesn't need to be perfect.
  2. Open prompt_A_with_spreadsheet.txt and copy everything inside it.
  3. Paste it as your first message to the assistant, and attach your filled-in spreadsheet to that same message.
Route B

Just chat about it

Best if you'd rather explain things in your own words and be asked questions.

  1. Open prompt_B_chat_only.txt and copy everything inside it.
  2. Fill in the bracketed part with a short description of your workflow.
  3. Paste it as your first message, and answer the assistant's follow-up questions as you go.

04What's included in the estimate

Included

  • Running the AI models themselves (the actual generation calls)
  • The minimal device & network footprint of triggering those calls

Not included

  • Training the AI models
  • Human work or review
  • Storage of the outputs beyond generation
  • Distribution or viewing of the final result

06If this is your first time

  • You don't need exact numbers. Rough, order-of-magnitude answers are enough for a useful first estimate.
  • You don't need to know any technical terms — describe things the way you'd explain them to a friend, and let the assistant translate.
  • It's normal for this to take a few back-and-forth messages, especially with Route B. That's expected, not a sign something's going wrong.
  • If a question confuses you, just say so — ask the assistant to rephrase it.
