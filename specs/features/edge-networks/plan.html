1.1 · Shared data: the hardware unit parent and the technology table

Files core/hardware/edge/edge_hardware_unit.py · core/hardware/edge/edge_device.py · core/hardware/edge/edge_device_group.py · core/hardware/edge/edge_network_technologies.py · constants/sources.py

What happens today. The "countable deployed unit" role lives on EdgeDevice as a cluster: parent_groups, _find_root_groups(), total_nb_of_units, the group-reference delete guard in self_delete(), lifespan with lifespan_validation, and the per-pattern sums instances_energy, use_footprint and instances_manufacturing_footprint. EdgeDeviceGroup.edge_device_counts is annotated as a weighted dict of EdgeDevice.

What is extracted. That cluster moves unchanged into an abstract EdgeHardwareUnit(ModelingObject). Subclasses answer two hooks: where their usage patterns come from, and the per-pattern unitary hourly energy and manufacturing. EdgeDevice keeps answering through its recurrent needs and components (its edge_usage_patterns, instances_energy_per_usage_pattern, use_footprint_per_usage_pattern and instances_manufacturing_footprint_per_usage_pattern stay where they are and keep their names, so the computed-attribute graph and every existing test are untouched). The gateway answers through its linked interfaces and constant inputs (1.4).

core/hardware/edge/edge_hardware_unit.py Proposed new parent (sketch)

class EdgeHardwareUnit(ModelingObject):
    """A deployed, countable piece of edge hardware: a device or a gateway. Sized by
    {class:EdgeDeviceGroup} counts, amortised over its lifespan, scaled per usage pattern."""

    parent_groups = ReverseCollection("EdgeDeviceGroup")

    @property
    @abstractmethod
    def edge_usage_patterns(self) -> List["EdgeUsagePattern"]: ...

    @computed_attribute(guard=True)
    def lifespan_validation(self): ...            # moved verbatim from EdgeDevice

    @computed_attribute
    def total_nb_of_units(self): ...              # moved verbatim from EdgeDevice

    def self_delete(self): ...                    # moved verbatim from EdgeDevice

    # instances_energy / use_footprint / instances_manufacturing_footprint:
    # sums over the subclass's *_per_usage_pattern dicts, moved verbatim.

edge_device_counts widens its annotation to WeightedExplainableObjectDict["EdgeHardwareUnit"]; the parameter description at param_descriptions says "device or gateway". The attribute and class names stay (kickoff decision 1b: the rename churn across both repositories is not worth the vocabulary gain). The interface's dict-relationship registry resolves (parent class, attribute, child class) from this annotation; the interface spec records that a gateway must resolve to the same attribute as a device through subclass matching.

Technology table. A module-level mapping from technology name to a dict of sourced default values, one column per technology, mirroring how EdgeWorkloadComponent.default_values and Network.archetypes() hold sourced defaults today. Each value is a SourceValue whose Source is a new entry in Sources (Morin 2017, Casals 2017, Bouguera 2018, Gomez 2019, Lauridsen 2018, Andres-Maldonado 2019, Kim 2019, Nordic SED 2023, Nordic nwp_049 2025, Malmodin 2018, Ruiz 2022, Pirson & Bol 2021). Values to pin come from the kickoff draft's §5 table; the SIGFOX triple transmission is a transmissions_per_message column (3 for SIGFOX, 1 elsewhere) rather than a code branch, so the only per-technology branches left are the operator rows of 1.5.

1.2 · Create a network interface from a technology

Files core/hardware/edge/edge_network_interface.py · core/hardware/edge/edge_network_technologies.py

The caller writes EdgeNetworkInterface.from_technology("LoRaWAN", p_sleep=...). The class method looks the column up, overlays the caller's keyword overrides and calls the constructor. The constructor is the ordinary EdgeComponent constructor with every physical parameter as an explicit input, so the interface serializes, edits and explains like any component. technology is a string SourceObject input with list_values, the pattern ServerTypes uses for server_type; it is a label and a validation key, not a switch (see decision D7).

core/hardware/edge/edge_network_interface.py Proposed class (constructor and factory)

class EdgeNetworkInterface(EdgeComponent):
    """Radio module of an {class:EdgeDevice}: LoRaWAN, SIGFOX, NB-IoT, BLE, WiFi (power-saving) or Thread.
    Draws a sleep floor, energy per message sent by its {class:RecurrentMessagingNeed}s and energy per
    synchronization exchange; links to an {class:EdgeGateway} or carries an operator-network share."""

    list_values = {"technology": [SourceObject(name) for name in EDGE_NETWORK_TECHNOLOGIES]}
    default_values = {**EDGE_NETWORK_TECHNOLOGIES["LoRaWAN"], "technology": SourceObject("LoRaWAN"),
                      "carbon_footprint_manufacturing_per_unit": SourceValue(2 * u.kg, Sources.PIRSON_BOL_2021),
                      "lifespan": SourceValue(6 * u.year), "packet_error_rate": SourceValue(0 * u.dimensionless),
                      "n_hops": SourceValue(1 * u.dimensionless)}

    @classmethod
    def compatible_root_units(cls):
        return ["message / second"]            # the messaging need's hourly messages

    @classmethod
    def from_technology(cls, technology: str, name: str | None = None, **overrides):
        defaults = {**cls.default_values, **EDGE_NETWORK_TECHNOLOGIES[technology],
                    "technology": SourceObject(technology)}
        return cls(name or f"{technology} interface", **{**defaults, **overrides})

    def __init__(self, name, technology, p_tx, p_rx, p_sleep, bitrate, overhead_per_frame,
                 max_payload_per_frame, energy_fixed_per_message, rx_listen_time_per_message,
                 sync_period, energy_per_sync, transmissions_per_message, packet_error_rate, n_hops,
                 operator_network_energy_per_device_hour, operator_network_embodied_per_device_hour,
                 carbon_footprint_manufacturing_per_unit, lifespan, edge_gateway: "EdgeGateway | None" = None,
                 nb_of_units=None):
        super().__init__(name, carbon_footprint_manufacturing_per_unit=..., lifespan=lifespan, nb_of_units=nb_of_units)
        ...  # set_label every input; power_per_unit / idle_power_per_unit are not inputs here

Lifespan. The kickoff draft says "inherited from EdgeDevice". The base component contract makes lifespan an input for core components, and EdgeDevice.unused_component_manufacturing_per_edge_device() raises when a need-less component's lifespan is a never-computed calculated attribute. An interface deployed at a pattern with no messaging need there would hit that error with an inherited lifespan. This draft keeps lifespan as an input defaulting to 6 years like every core component (decision D1).

Per-message energy. Computed once per interface from inputs, as a calculated attribute the messaging flow multiplies by the hourly message count. Not a timeseries: payload size is a scalar on the need, so the product is taken per need in 1.3.

core/hardware/edge/edge_network_interface.py Proposed per-message physics (kickoff §4, unchanged)

def energy_per_message(self, payload_size: ExplainableQuantity) -> ExplainableQuantity:
    nb_frames = ceil(payload_size / self.max_payload_per_frame)
    bits_per_frame = (payload_size / nb_frames).to(u.bit) + self.overhead_per_frame
    nb_transmissions = self.transmissions_per_message / (1 - self.packet_error_rate)
    airtime = nb_transmissions * nb_frames * bits_per_frame / self.bitrate
    return self.n_hops * (self.energy_fixed_per_message + airtime * self.p_tx
                          + self.rx_listen_time_per_message * self.p_rx)

1.3 · Attach a messaging need and compute hourly interface energy

Files core/usage/edge/recurrent_messaging_need.py · core/hardware/edge/edge_network_interface.py · constants/units.py

The caller writes RecurrentMessagingNeed("readings", edge_component=interface, messages_per_hour=..., payload_size=...) and lists it in a RecurrentEdgeDeviceNeed like any component need. Making it a subclass of RecurrentEdgeComponentNeed (the precedent is RecurrentEdgeStorageNeed) resolves the kickoff's open point 3: the component's edge_usage_patterns, the pattern's containment_inventory and the device's attribution atoms all walk component needs, so a separate hierarchy would have to re-create every one of those paths.

core/usage/edge/recurrent_messaging_need.py Proposed class

class RecurrentMessagingNeed(RecurrentEdgeComponentNeed):
    """Messages an {class:EdgeNetworkInterface} sends over a typical week, with their payload size."""

    def __init__(self, name, edge_component: "EdgeNetworkInterface",
                 messages_per_hour: ExplainableRecurrentQuantities, payload_size: ExplainableQuantity):
        super().__init__(name, edge_component)        # recurrent_need is computed below
        self.messages_per_hour = messages_per_hour.set_label("Messages per hour")
        self.payload_size = payload_size.set_label("Payload size")

    @computed_attribute
    def recurrent_need(self):
        """Alias so the base validation and hourly replay see messages per hour as the component need."""
        return self.messages_per_hour.copy().set_label("Recurrent need")

With recurrent_need aliased, recurrent_need_validation checks the unit against the interface's compatible_root_units (hence the new message unit in the custom units file loaded by units.py), and unitary_hourly_need_per_usage_pattern replays the week over the deployment calendar, scaled by containment occurrences, exactly as for CPU or RAM needs. Nothing else in the need base class changes.

Hourly power of the interface. The component's required hook unitary_power_per_usage_pattern sums the three terms over the messaging needs reaching the pattern, found through the existing recurrent_needs_in_usage_pattern(). Its shape mirrors EdgeWorkloadComponent.unitary_power_per_usage_pattern: a floor plus a demand-driven term on the need's hourly axis.

core/hardware/edge/edge_network_interface.py Proposed hourly power (sketch, Δt = 1 h)

@computed_dict(keys="edge_usage_patterns")
def unitary_power_per_usage_pattern(self, usage_pattern):
    one_hour = ExplainableQuantity(1 * u.hour, "one hour")
    messages = sum(need.unitary_hourly_need_per_usage_pattern[usage_pattern]
                   for need in self.recurrent_needs_in_usage_pattern(usage_pattern))   # messages / hour
    message_energy = sum(need.unitary_hourly_need_per_usage_pattern[usage_pattern]
                         * self.energy_per_message(need.payload_size) for need in ...)  # J / hour
    syncs = maximum(0, one_hour / self.sync_period - messages * one_hour)               # 0 when sync_period is inf
    return (self.p_sleep + message_energy / one_hour
            + syncs * self.energy_per_sync / one_hour
            + self.operator_network_energy_per_device_hour / one_hour).set_label(...)

@property
def unitary_power_at_zero_recurrent_need(self):
    """Sleep floor plus the idle keep-alive cost: what the radio draws when no message is sent."""
    return self.p_sleep + self.energy_per_sync / self.sync_period + self.operator_network_energy_per_device_hour / one_hour

From there the existing component chain does the rest: energy_per_edge_device_per_usage_pattern multiplies by parallel deployments, the device sums it in instances_energy_per_usage_pattern times total_nb_of_units, and the attribution layer's energy_atom_value_per_need_and_pattern splits the floor equally among the interface's needs and the rest by demand share, which the demand_share_per_need_and_pattern computes from unitary_hourly_need_per_usage_pattern (messages per hour). The sync term is not linear in message count, but shares still sum to one per hour, so atoms still partition the component's use footprint exactly.

Radio module fabrication flows through the unchanged manufacturing_footprint_per_edge_device_per_usage_pattern. The operator embodied share joins it in 1.5.

1.4 · Link an owned gateway and count it

Files core/hardware/edge/edge_gateway.py · core/hardware/edge/edge_network_interface.py · core/hardware/edge/edge_hardware_unit.py · core/hardware/edge/edge_device_group.py

The caller writes EdgeGateway("farm LoRa gateway"), assigns it to interface.edge_gateway (a plain forward link, so ModelingUpdate handles reassignment like any object link) and puts it in a group: EdgeDeviceGroup("farm", edge_device_counts={device: 80, gateway: 1}).

core/hardware/edge/edge_gateway.py Proposed class

class EdgeGateway(EdgeHardwareUnit, AttributionSource):
    """User-owned concentrator between device radios and the IP backhaul: LoRaWAN gateway, Thread border
    router, BLE hub, WiFi access point. Draws constant power; sized by {class:EdgeDeviceGroup} counts."""

    default_values = {"power": SourceValue(5 * u.W, Sources.HYPOTHESIS),
                      "carbon_footprint_fabrication": SourceValue(25 * u.kg, Sources.PIRSON_BOL_2021),
                      "lifespan": SourceValue(6 * u.year)}

    edge_network_interfaces = ReverseCollection("EdgeNetworkInterface")

    @property
    def edge_usage_patterns(self):
        return list(dict.fromkeys(sum([i.edge_usage_patterns for i in self.edge_network_interfaces], start=[])))

    @computed_dict(keys="edge_usage_patterns")
    def instances_energy_per_usage_pattern(self, usage_pattern):
        return (self.power * one_hour * usage_pattern.nb_deployments_in_parallel * self.total_nb_of_units).set_label(...)

    @computed_dict(keys="edge_usage_patterns")
    def use_footprint_per_usage_pattern(self, usage_pattern):
        return (self.instances_energy_per_usage_pattern[usage_pattern]
                * usage_pattern.country.average_carbon_intensity).to(u.kg).set_label(...)

    @computed_dict(keys="edge_usage_patterns")
    def instances_manufacturing_footprint_per_usage_pattern(self, usage_pattern):
        return (self.carbon_footprint_fabrication / self.lifespan * one_hour
                * usage_pattern.nb_deployments_in_parallel * self.total_nb_of_units).to(u.kg).set_label(...)

    def attribution_atoms(self, phase): ...   # see below

The three per-pattern dicts are the gateway's answers to the parent's hooks; the parent's summed instances_energy, use_footprint and instances_manufacturing_footprint (moved from EdgeDevice in 1.1) make the gateway a top-level footprint source like Network. The lifespan_validation guard applies unchanged, raising InsufficientCapacityError when a pattern's usage span exceeds the gateway's lifespan. total_nb_of_units reads the widened edge_device_counts and defaults to one per deployment when the gateway is in no group.

Refusing operator-side links. A guard on the interface, edge_gateway_validation, raises a ValueError when edge_gateway is set and the technology column has requires_gateway=False. It is a guarded computed attribute like recurrent_need_validation, so it re-runs on both technology and gateway edits. Nothing forces a gateway on the four owned technologies: a missing gateway simply contributes nothing, and the interface spec decides how to prompt for one.

Sankey atoms. AttributionSource requires attribution_atoms(phase). The gateway's per-pattern value splits across the messaging-need paths of its linked interfaces, weighted by each path's device total_nb_of_units times occurrences, so the sum of atoms equals the gateway's footprint. The shape copies Network.attribution_atoms() (one atom per containment cell) and EdgeDevice.attribution_atoms() (occurrence shares over containment_inventory.component_need_paths). This is the "cheap optional view" of kickoff §3.3; no further user-facing breakdown is planned (spec open question 4).

1.5 · Operator-side technologies: NB-IoT and SIGFOX

Files core/hardware/edge/edge_network_interface.py · core/hardware/edge/edge_network_technologies.py

No object. Two sourced per-device-hour inputs on the interface, zero for the four owned technologies. The energy row is already folded into unitary_power_per_usage_pattern in 1.3 (Wh per device-hour divided by one hour is a power), so it flows through the component's use footprint and the country carbon intensity with no extra path. The embodied row joins the component's manufacturing axis by overriding manufacturing_footprint_per_edge_device_per_usage_pattern on the interface: base amortization plus operator_network_embodied_per_device_hour × nb_deployments_in_parallel. Both terms carry labels naming the operator network so the explainability graph shows them as distinct ancestors. Allocation key is time per subscriber, never per gigabyte (Mytton 2024, ITU-T L.1410).

Values to pin: Malmodin 2018 gives about 20 kWh per mobile subscription per year (≈ 2.3 Wh per hour); Ruiz 2022 gives 81 to 103 kg CO2e per subscription per year including embodied, to be split. Until pinned, the column may ship flagged Sources.HYPOTHESIS values (spec open question 3).

3. Decisions for review

Where this draft departs from or sharpens the kickoff draft. Each is a design choice within the spec's scope; the spec-plan stage confirms or changes them.

D1 · Interface lifespan is an input (default 6 years), not inherited from the device.
Kickoff said "inherited". Inheriting means a computed lifespan, which the need-less-component booking in unused_component_manufacturing_per_edge_device() cannot read. An input keeps the base component contract and lets a radio module outlive or outlast its host.
D2 · RecurrentMessagingNeed subclasses RecurrentEdgeComponentNeed, with recurrent_need computed from messages_per_hour.
Resolves kickoff open point 3. Reuses validation, weekly replay, containment paths and attribution unchanged. Alternative (a parallel need hierarchy) would duplicate four traversal paths and the atom builder.
D3 · No payload-to-network data path.
Spec open question 1; recommendation stated there. If the user wants the second path, it is a new Network consumer beside use_footprint_for_data_volume_and_usage_pattern() plus a rule to avoid charging the same bytes through jobs; plan it only on request.
D4 · No LoRaWAN spreading-factor input.
Spec open question 2. Bitrate and maximum payload are per-interface inputs; the docs tabulate SF7 to SF12.
D5 · EdgeGateway is its own canonical class in the Sankey infrastructure column, listed under the existing "EdgeDevices" object category.
Own class: the Sankey and system breakdown need a distinct line. Existing category: avoids a new interface column for one object type; the interface spec can still give it its own Add button.
D6 · No schema version bump.
Only additive classes and an annotation widening with the same on-disk shape. Confirm against the constitution's serialization gate during planning; bump if any existing object's JSON changes.
D7 · technology is a string SourceObject with list_values, not a Python Enum.
Matches how other choice inputs serialize and how the interface renders selects; the technology table is keyed by the same strings. The table also carries a requires_gateway flag used by the link guard and by the interface to hide the gateway control.
