1.1 · Resolve a saved formula on display

Status. Implemented as planned. The resolver body differs from the snippet in two lines; the note under the snippet says which.

Files efootprint/abstract_modeling_classes/explainable_object_base_class.py

A user opens a saved footprint in the side panel. The view get_calculated_attribute_explanation() calls the presenter, which reads explain_nested_tuples. For a value attached at load, that property deserializes the stored tree on first access and resolves each string leaf through get_attribute_from_flat_obj_dict(), which today peeks via peek_attribute_value(): a void operand becomes None, and _compute_formula_as_flat_tuple() drops the leaf but keeps its operators. That is the * ( / ( * one hour ) ) rendering.

Change. The resolver reads the attribute through ordinary attribute access, so a void computed slot is pulled by computed_attribute.__get__() A key address on an input dict indexes that dict. A key address on a computed dict indexes the dict facade (computed_dict.facade(), found through computed_slots() of the container's class) instead of reading the attribute. The facade's __getitem__ pulls only that key's sub-slot and raises for a key outside the key collection. Reading the attribute would go through computed_dict.__get__(), which pulls the key-set slot, whose closure pulls every element (line 276). Stored formulas do hold element addresses: freshly computed and saved, the complex integration system's formulas hold 17 element addresses out of 69 operand addresses, all elements of use_footprint_per_job, use_footprint_per_usage_pattern or instances_manufacturing_footprint_per_usage_pattern. Measured on that system, saved and reloaded, resolving one use_footprint_per_job element costs 73 computations through the attribute and 20 through the facade. The extra computations are sibling elements the formula does not show, which the spec's constraint "explanation requests compute only the values they display" excludes. The facade item read is the path the engine already uses to read one element inside a computation, so no new engine path is introduced. The peeking body and its "never computes" docstring go.

efootprint/abstract_modeling_classes/explainable_object_base_class.py Proposed body of get_attribute_from_flat_obj_dict (replaces the peeking one). Differs from the final code: the container class comes from container.efootprint_class and the reactive helpers are imported locally.

def get_attribute_from_flat_obj_dict(attr_key: str, flat_obj_dict: dict):
    """Resolve a serialized (container id, attribute[, key id]) address to its live value, computing a
    void computed slot. Only the formula deserializer calls this, on display: an operand of an
    explanation is part of what is being explained. A computed-dict element is read through the dict
    facade, which computes that element only."""
    container_id, attr_name, key_id = _parse_value_address(attr_key)
    container = flat_obj_dict[container_id]
    if not key_id:
        return getattr(container, attr_name)
    descriptor = computed_slots(type(container)).get(attr_name)
    if isinstance(descriptor, computed_dict):
        return descriptor.facade(container)[flat_obj_dict[key_id]]
    return getattr(container, attr_name)[flat_obj_dict[key_id]]

Why pulling here is safe, verified in this checkout:

  • After 1.2 removes the hydration path, the formula deserializer is the only caller of the resolver (today it has two: the formula at line 221 and load_ancestors_and_children_from_json() at lines 255 and 260).
  • Nothing reads explain_nested_tuples inside a computation. The compute closures only call record_calculus_edges_from_ancestry(), which reads direct_ancestors_with_id of the value the getter just returned; that value is fresh, so 1.2 serves it from the in-memory list without touching a stored formula.
  • Saving never deserializes: to_json() re-emits explain_nested_tuples_from_json when it is set, and the getter never clears it (only the setter does). The displayed-then-saved value therefore serializes byte-for-byte as before display.
  • The display runs outside any compute frame, so the pulls record no dependency edges; the pulled values attach to their slots exactly as a results-page read would attach them.

1.2 · Direct ancestors derived from the formula

Status. Implemented as planned; the snippet matches the final code.

Files efootprint/abstract_modeling_classes/explainable_object_base_class.py

The calculus graph page's display_calculus_graph() hands the value to build_calculus_graph(), which walks direct_ancestors_with_id recursively and calls explain() on every node. For a loaded value the property runs load_ancestors_and_children_from_json() once, from the loader's inversion pass (1.4), while every non-serialized operand is void: addresses resolve to None, are filtered, and the _graph_links_hydrated_from_json flag prevents any later re-resolution. Measured: zero of six ancestors, before and after the operands are computed.

By construction a value's direct ancestors are the attached leaves of its formula: compute_explain_nested_tuples() collapses the parent tree at exactly the nodes that return_direct_ancestors_with_id_to_child() keeps (attached values), and both walk left parent before right parent, so a left-to-right leaf walk deduplicated by id reproduces the in-memory list and its order. Unattached leaves (inline constants, and intermediate nodes without ancestors) are excluded by both, as today.

1.3 · Direct children from the slot graph, with links that describe current values

Status. Implemented with linked decisions: the engine invariant as planned, the rollback re-pull changed by IMPL-DECISION-01, the stored-list removal and the purpose query removal by PLAN-UPDATE-02 and PLAN-UPDATE-04.

Files explainable_object_base_class.py · reactive_core/graph.py · reactive_core/computed_slots.py · modeling_object.py

The side panel's Direct children list calls the presenter's web_children(), which reads direct_children_with_id. Today the list is filled at load by invert_children_links_of_stored_values() from cached values only (and, in memory, by the bookkeeping in set_modeling_obj_container()), so void dependents never appear. A formula cannot supply children: void values have no formula. The slot graph can, since rebuild_dependency_graph() reinstalls every edge at load, values or not. Reading it as "which values use this one" requires its links to be exact, which the engine does not guarantee today. This step makes it guarantee that, then derives children from it.

Engine invariant: a slot's links are the reads of its current state

A slot's dependency links are the reads that produced its current state: its cached value, its last failed or rejected attempt, or, for a void slot installed at load or an evicted transient structure, the reads of the value it last held. A slot emptied by invalidation, removed from its owner or owned by a deleted object has no links. Today three paths break this:

  • Invalidation keeps links. invalidate() voids a slot and leaves its links in place until it recomputes. When the recompute takes another branch, the old links were wrong in the meantime: after a switch from on-premise to autoscaling, nb_of_instances stays linked to fixed_nb_of_instances, which only _on_premise_nb_of_instances() reads.
  • A failed or rejected computation discards its reads. ReactiveSlot._compute() installs the frame's reads only after the getter returns (line 172); when it raises, the slot keeps the links of its previous success. When a computation observer rejects the result, the engine restores those previous links (line 178). If the failing attempt went down a branch whose reads the previous links lack, a later write to those reads cannot reach a dependent that cached a fallback, the case test_failed_compute_clears_marker_so_next_wave_reaches_fallback_caching_dependent builds.
  • Slots that leave the model keep links. computed_dict.discard_stale_keys() pops a stale sub-slot from its owner's registry (line 263), and ModelingObject.self_delete() drops its slots' values (line 686); both leave the slots linked. Replaying run_test_add_usage_pattern up to its post-reset loop, the country's carbon intensity keeps six explainable calculus dependents; one is the new device's use_footprint_per_usage_pattern sub-slot keyed by the deleted pattern, and pulling it raises KeyError. The country's timezone keeps the deleted pattern's utc_hourly_occurrences. The save boundary already filters such slots out (calculation_graph_section(), line 156); in memory nothing does.

None of these produces a wrong result today, because invalidation tolerates surplus links. They matter to any reader of the graph as a relation: the children list below, and the exported computation_slots_for_purpose(), which keeps classifying a void output through its retained links. Its test test_purpose_query_keeps_invalidated_materialized_topology pins that retention on purpose, and after a branch switch the same retention returns the stale branch's computations. Nothing outside its tests calls it, and the purposes= tags on footprint outputs exist only to feed it, so this feature removes the query rather than adapting it (PLAN-UPDATE-04).

Proposed engine change. Invalidation cuts the links of every slot it voids, and every computation outcome (success, failure or rejection) installs the reads of that attempt:

efootprint/abstract_modeling_classes/reactive_core/graph.py Proposed: invalidation cuts links; every computation outcome installs its reads. Abridged: the final code also refuses invalidation inside a computation and reports voided slots to the collector (invalidate()), and wraps the getter in the computation stack and the observer hook (ReactiveSlot._compute()).

def invalidate(*slots):
    ...
    while work:
        slot = work.pop()
        if slot._wave_passed:
            continue
        slot._wave_passed = True
        slot._drop_value()
        visited.add(slot)
        work.extend(slot._dependents)
        slot.replace_dependencies()  # a void slot reads nothing until it recomputes
    ...

class ReactiveSlot:
    def _compute(self):
        ...
        try:
            value = self.getter()
        finally:
            _compute_stack.reset(token)
            self._wave_passed = False
            # Success or failure, the links are this attempt's reads: whatever made it fail was read first.
            self.replace_dependencies(frame.calculus_reads, frame.structural_reads)
        self.attach_cached_value(value)
        if observer is not None:

            except Exception:
                self._drop_value()  # rejected: void, linked to the reads that produced the rejected value
                raise

work.extend runs before the cut, so the wave still reaches the slot's dependents; the cut removes the slot from its dependencies' _dependents, never its own. In discard_stale_keys() each popped stale_slot calls replace_dependencies(), and so does each slot in the drop loop of self_delete(). The observer path loses its previous_calculus_dependencies / previous_structural_dependencies bookkeeping (line 161).

Unchanged, and why it stays sound:

  • Load. Loaded void intermediates keep their installed links until the first wave reaches them, and that wave voids the stored values above them too, as the invalidate() docstring requires.
  • Transient eviction. computed_structure.evict_cached_value() drops a value without invalidating, so the evicted structure keeps its links and the cached values above it still invalidate.
  • Wave pruning. A marked slot's dependents are marked by the same wave before its links are cut; a marked void slot that nothing reaches any more is unmarked by its next compute, success or failure.
  • Rollback. ModelingUpdate.rollback() writes the old inputs back, invalidates from the same input nodes, then re-pulls the guards the forward wave visited together with those its own wave voids. Reading a plain input such as server_type records nothing: input edges come only from the returned value's ancestry, so a guard that raised is linked only to the computed slots it read, and the rollback wave alone could not reach it. The explicit re-pull recomputes it on the restored inputs, and its links then describe the on-premise branch (IMPL-DECISION-01).

[IMPL-DECISION-01] — APPLIED

Material plan difference and a newly discovered pre-existing defect, fixed in run A (Task 1 review).

The plan argued that a guard rejected under a new server_type would be re-linked by the rollback wave because it "read server_type before raising". That is false: reading a plain explainable input records nothing in the compute frame. Input edges are only installed from the returned value's ancestry by record_calculus_edges_from_ancestry, which never runs for an attempt that raised. With reads installed in the finally of ReactiveSlot._compute as planned, a rejected capacity guard is linked only to raw_nb_of_instances, so the rollback wave from the input nodes never reaches it and it stays void. Displayed values stay correct because a void slot recomputes when read, and no getter in efootprint catches exceptions; the limit is stated under "Links are the reads of the current state".

Investigating this exposed a pre-existing defect with the same root cause on the old engine: an invalid guarded edit submitted through ModelingUpdate without eager outputs was rejected once, then accepted when repeated, because the failed guard never cleared the input's wave marker and no wave pulled it again. The fix, applied in ModelingUpdate.__init__ and ModelingUpdate.rollback, passes the forward wave's visited slots into rollback, which re-pulls their guards together with its own wave's. No filter for newly linked objects was needed: re-pulling the guard of a detached, previously computed standalone object does not raise again, as test_rejected_link_to_a_computed_standalone_object_rolls_back_without_reraising checks. The regression test_repeated_invalid_guarded_edit_is_rejected_each_time rejects the same edit twice and finds the guard cached and linked to fixed_nb_of_instances and server_type after rollback. Effect: the "Branch switch and rollback" verification row holds through the explicit re-pull rather than through wave reachability, and rollback now costs one extra pull per guard the forward wave visited. Remaining gaps, accepted: a getter that caught a failure and cached a fallback would not be linked to inputs its failed branch read (no such getter exists); and a newly linked object whose own guard fails and reads a node that the rollback's detach changes would, now that failed attempts are linked, land in the rollback wave and raise again (the global review probed never-computed, previously computed and intrinsically invalid new servers and found no producer).

Planned fix: the parked backlog plan automatic input-read dependencies records an edge for every input read during a computation, which closes the fallback-getter gap and makes a rejected guard reachable from its inputs by the rollback wave alone. Once it lands, remove the forward_visited_slots argument of ModelingUpdate.rollback and the call passing it from ModelingUpdate.__init__; the two regression tests above must keep passing without them.

Accepted consequence: a value emptied by an edit lists no children until its consumers recompute. In the interface the eager footprint pull recomputes the edited cone in the same request, so the saved graph is current. Cost, measured on the big performance system for the input with the largest dependents cone (a UsageJourneyStep's user_time_spent, 202 invalidated slots): edit plus recompute 36 ms today, 37 ms with cutting, of which 0.2 ms cutting (monkeypatched, single laptop runs).

Children: the calculus dependents of the slot, pulled

efootprint/abstract_modeling_classes/explainable_object_base_class.py Proposed property replacing the stored list (local import of slot_of_attached_value, as the module already does for other engine helpers). Matches the final code.

@property
def direct_children_with_id(self):
    """Attached values whose formula uses this value: the calculus dependents of its slot, pulled."""
    if self.modeling_obj_container is None:
        return []
    slot = slot_of_attached_value(self)
    children = []
    for dependent in slot.dependents:
        # Only slots that attach an explainable value to their owner (computed attributes and
        # computed-dict elements) are children; bump nodes, key-set nodes and computed structures are not.
        if dependent.on_value_dropped is None or slot not in dependent.calculus_dependencies:
            continue
        children.append(dependent.pull())
    return children

slot_of_attached_value() gives the node for a computed value through its backpointer and for an input through its bump node, so one property serves both; the same resolution already serves record_calculus_edges_from_ancestry(). dependents is the union of calculus and structural readers. Two filters, both applied before pulling:

  • slot in dependent.calculus_dependencies (line 135) keeps formula consumers and drops structural-only readers, as the decision record asks.
  • dependent.on_value_dropped is not None (line 101) keeps the slots that hold an attached explainable. Only computed_attribute.slot() and computed_dict.sub_slot() pass _release_value; the computed-dict key-set node (_on_value_dropped = None) and computed_structure.slot() do not. Without this check a child listing could pull a computed structure (the key-set closure at line 276 pulls every element of its dict) and then discard the non-explainable result. See decision 1 for the marker choice.

Because links are current, every listed dependent reads this value in its current or last attempted state; the pull only computes void children. Measured on the saved and reloaded GenAI video example (baseline table): the heaviest list, the children of the country's carbon intensity, pulls seven dependents through 82 computations in about 5 ms. The spec's "bound the list?" question is answered: no bound. A dependent whose getter raises propagates the error to the request, exactly as opening a non-serialized attribute does today; no recovery is added. Objects detached without deletion (a network left behind by a rollback) keep their links while they still read the value, and are listed as live in-memory consumers; a reloaded model never holds them.

[IMPL-DECISION-02] — APPLIED

Newly discovered pre-existing defect, fixed in run A (Task 2 review).

The save traversal in recursively_write_json_dict discovered objects through peeked computed values as well as inputs: computed-dict keys were queued for writing and computed facades were followed through their containers, so the order of objects and of the top-level class blocks depended on what happened to be cached. A canonical round trip was therefore not byte-identical even before this feature (the existing round-trip tests compared dicts, which hid it), and after 1.1 merely building a loaded model's calculus graph then saving reordered the file. Objects are now discovered through inputs and input dicts only; computed values contribute sources only. On every fixture the written object and source sets are unchanged for System roots. The three committed reference files (simple_system.json, complex_system.json, system_with_services.json) were regenerated with order as the only difference. Content does change in one state no fixture holds: an object that still drives the system's computations through reverse links without being reachable from the system's inputs (an EdgeUsagePattern unlinked from its System but not deleted) was written by the old traversal and is dropped by this one, so an inputs-only reload loses what it drove. The interface cannot produce that state (it removes objects through self_delete only); the library can. The root cause is that membership is declared forward while footprints aggregate backward; the backlog seed connectivity-defined system membership carries the discussion and the measured divergence. The round-trip tests run_test_explanation_links_survive_round_trip and run_test_displaying_one_stored_formula_computes_only_its_operands now compare serialized bytes, calculation graph included, which is the acceptance the task stated. The interface is unaffected: ModelWeb.to_json iterates its own flat object dict. The "Saving peeks, never pulls" rule in persistence.html gained the clause that bytes do not depend on what is computed.

[IMPL-DECISION-03] — APPLIED

Newly discovered pre-existing defect fixed in run A (Task 4, added by the supervisor after the Task 2 review), with substantial lasting complexity: a new node-key form in the saved calculation graph.

The calculation-graph section promises that reinstalled edges let later edits reach cached serialized values. It skipped every computed-dict sub-slot whose key is not a serialized object, and the attribution dicts Job.hourly_avg_occurrences_per_coordinate and hourly_data_transferred_per_coordinate are keyed by JobOccurrenceCoordinate (and the step-occupancy weight by UsageJourneyStepCoordinate). After a reload, an edit to Job.data_transferred or UsageJourneyStep.user_time_spent therefore never reached the stored System.impact_repartition_matrix or EdgeDevice.footprint_breakdown_summary, which stayed cached and stale (reproduced before Task 1, so pre-existing). The same skip was what left children incomplete after reload for those keys, the one plan row Task 2 could not deliver.

Fix: a key class implements to_json_key / from_json_key (components by object id; same pair on UsageJourneyStepCoordinate) and is registered in COMPUTED_DICT_KEY_CLASSES_DICT. _slot_address keeps a hashable address, _json_node writes the key as {"ClassName": {component: id}}, and _key_object_ids applies the foreign-id skip to object keys and coordinate components alike. At load _dict_key_from_json rebuilds the key by dict lookups only, so loading still computes nothing, and a rebuilt coordinate compares equal to one built at compute time because modeling objects hash by id. api_utils keeps no coordinate special case. The foreign-component skip is load-bearing: unlinking an EdgeUsagePattern from the system without deleting it leaves coordinate sub-slots keyed by the unwritten pattern, which test_coordinate_with_an_unsaved_component_is_skipped_at_save reaches through that path. Evidence: run_test_editing_a_reloaded_model_voids_its_stored_summaries on every fixture compares the voided stored slots and recomputed values after a reload with the same edit in memory (fails on the pre-task code on all six web fixtures; the edge-only fixtures have no such input and assert nothing).

Cost accepted: the saved graph now has a third node-key form (null, object id, or class-keyed components); every future non-object computed-dict key class must implement the pair and be registered, or its invalidation edges are silently lost at save (stated in specs/conventions.md and persistence.html). On the big performance system: +386 nodes, file +11.6% (3.40 MB to 3.79 MB), load and save each +2–4 ms. Older files keep loading since the nodes are additive, and the Task 3 version bump demotes their stored values to the comparison baseline anyway. No schema handler is needed.

3. Decisions for review

1 · Which slots count as children — ACCEPTED 2026-10-19: reuse the drop callback

The children filter in 1.3 must skip computed structures and key-set nodes before pulling. The proposal reads on_value_dropped, which only the two explainable-holding slot kinds set, with a comment at the filter. The alternative is an explicit boolean on ReactiveSlot.__init__() set by the same two descriptors. Decision: reuse the callback; it already encodes "this slot attaches an explainable to its owner", and a second flag would have to be kept in step with it.
