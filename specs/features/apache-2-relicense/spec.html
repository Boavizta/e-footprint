Apache-2 relicense

Status: Spec — under review · 2026-07-03 · This is a licensing/governance feature with one packaging-level code change; it modifies no modeling logic.

1. Problem and audience

  • Problem. e-footprint is AGPL-3.0. Enterprise open-source policies ban AGPL mechanically: software-composition-analysis scanners flag it anywhere in a dependency tree and corporate policy says no, regardless of the legal merits of any particular use (observed signal: Schneider Electric-type policies; Google bans AGPL outright). The protection AGPL was chosen for — deterring a proprietary "improved core" product — is largely symbolic in practice: internal use is untouched by any license, violations at distribution/SaaS level are hard to detect, and the project's real defense is maintainer velocity and standard-setter status. Meanwhile the roadmap's calibration direction requires e-footprint to be embedded inside enterprise data platforms — the most license-sensitive place software can live. The cost side of the AGPL trade has grown; the benefit side was always thin.
  • An incoherence today: e-footprint-interface is Apache-2.0 and imports the AGPL library. For Publicis Sapient (copyright holder of both) this is fine; for any third party deploying the interface, it inherits the contested combined-work question. The two co-developed artifacts currently make a licensing statement that contradicts itself.
  • A hidden blocker: relicensing the code alone would be cosmetic — efootprint declares a required pip dependency on boaviztapi, which is AGPL-3.0. Scanners evaluate the installed tree. The dependency is only an opt-in / fallback execution path (the hosted HTTP API is already the primary path), so it can become optional.
  • Audience. Enterprise adopters and integrators (the calibration mission's targets); Publicis Sapient as copyright holder; the Boavizta ecosystem; future contributors.
  • Why now. The calibration feature is about to start and should be born under the final license; the external-contributor surface is tiny today (a handful of people), making consent cheap now and costlier every year; an active client context (Schneider) is supplying direct evidence of the adoption cost.

2. Success criteria

  • The next release is published under Apache-2.0: LICENSE file, NOTICE file, [project] license metadata and classifier, README license section, CHANGELOG entry all consistent. Previously published versions remain AGPL (unavoidable and acceptable).
  • Default pip install efootprint contains zero AGPL code in its dependency tree, verified by a license-audit step in CI. Boavizta impact data remains available through the hosted HTTP API (primary path today), a configurable self-hosted API URL, and the bundled data snapshot; the in-process boaviztapi package becomes an optional extra with an actionable error message when absent.
  • The full test suite passes without the optional extra installed.
  • Written relicensing consent from every external contributor (or their contributions rewritten), recorded publicly (e.g. a dedicated GitHub issue).
  • Publicis Sapient sign-off documented; Boavizta informed before the public announcement, with the collaboration framing (their AGPL methodology core stays protected; e-footprint extends its reach into enterprises that would never consume AGPL directly).
  • A DCO (Developer Certificate of Origin) requirement is adopted for future contributions, keeping provenance clean and future licensing options open.
  • Attribution note added for the bundled Boavizta data snapshot, referencing Boavizta's data terms.
  • specs/mission.md license line and any docs mentions updated; a public announcement explains the adoption-first rationale.

3. Scope

Capability-level only; file-level mechanics live in plan.html.
In scope
  • License change of the e-footprint library for future versions.
  • Making the AGPL boaviztapi package an optional install extra, with hosted HTTP API (existing primary path), self-hosted API URL, and bundled snapshot as the supported default paths.
  • Contributor-consent process and its public record.
  • Governance follow-through: DCO adoption, NOTICE/attribution, comms.
Out of scope (this feature)
  • Relicensing already-published releases (legally moot; they stay AGPL).
  • Any change to e-footprint-interface (already Apache-2.0).
  • Asking Boavizta to relicense BoaviztAPI (their call; a separate conversation this feature merely opens).
  • Changing other dependencies (EcoLogits is MPL-2.0, which composes cleanly inside an Apache-2 project).
  • CLA infrastructure beyond a lightweight DCO.

5. Constraints

  • This is a Publicis Sapient decision (copyright holder); this spec is the decision memo, not the decision. External contributions are few but real — consent or rewrite is a hard gate before the license swap ships.
  • Near-one-way door: future versions could be relicensed again, but permissive→restrictive moves carry community fork risk (Elastic, HashiCorp precedents). The decision should be made once, deliberately.
  • Fallback position: if PS or Boavizta conversations require a reciprocity gesture, MPL-2.0 (file-level copyleft: modifications to e-footprint files must be shared, everything built around it unencumbered) is the named fallback — not AGPL.
  • Constitution: silent on licensing; no conflict. specs/mission.md documents the license and must follow.
