Technical glossary

Canonical definitions for Python and recomputation terms used throughout the architecture. Pages give short local context; these entries carry the stable meaning and e-footprint-specific interpretation.

Backpointer

A reference stored on a child object that points back to the object or runtime node that owns it.

In e-footprint: an attached explainable value's _reactive_slot points to the stable slot for its modeling-object attribute. The engine uses it to map formula ancestry back to dependency-graph addresses.

Related: ReactiveSlot, calculus dependency.

Calculus dependency

A recomputation edge saying that a calculated attribute consumed a numerical or explainable input value.

In e-footprint: the engine derives these edges from ExplainableObject formula ancestry. If the consumed value changes, the calculated slot becomes void.

Contrasts with: structural dependency.

Class namespace

The temporary name-to-object mapping Python builds while executing a class body; it later becomes the new class's dictionary.

In the decorator example: Python first binds the method name to the function, then rebinds that same name to the descriptor returned by computed_attribute(function).

Related: decorator, descriptor.

Closure

A function that retains references to names from the surrounding scope where it was created, even after that outer call has returned.

In e-footprint: _make_compute_closure() returns a zero-argument function that remembers the descriptor, modeling-object instance, and slot needed for one computed attribute.

More specific: getter closure.

ContextVar

A Python variable whose value is local to the current thread or asynchronous execution context, rather than being one mutable global shared by concurrent work. set(value) returns a token; reset(token) restores the exact previous value after nested work or an exception.

In e-footprint: it holds an immutable tuple used as the active computation stack. A getter pushes its frame, structural read hooks and calculus ancestry recorders add dependencies to the top frame, and finally resets the token when the getter exits.

Decorator

A callable that Python applies to a function or class declaration using @name syntax; the callable's return value replaces the declared object under that name.

In e-footprint: @computed_attribute receives the domain getter and returns the descriptor that Python installs on the model class.

Related: descriptor, getter.

Descriptor

An object stored on a Python class that defines one or more attribute-access hooks such as __get__, __set__, or __delete__.

In e-footprint: the computed_attribute object is a descriptor. Its __get__ returns itself for a class read and pulls the correct per-instance slot for an instance read.

A descriptor is not inherently a decorator; this implementation deliberately plays both roles.

Eager output

An observable result that the update transaction deliberately reads after invalidation, causing the pull-based graph needed for that result to recompute.

In e-footprint: the default boundary is System.total_footprint. Passing eager_outputs=() leaves invalidated results void until a later explicit read.

Eager sweep

The fallback pass that immediately pulls eligible slots visited by an invalidation wave instead of waiting for a later attribute read.

In e-footprint: it runs only when eager_outputs has its default value and the changed object belongs to no System, leaving no System-total recomputation root. It skips getter-less, discarded, and lazy slots and orders the rest by pull_precedence. Its purpose is to surface failures inside an internally connected standalone fragment while the update can still roll back; a genuinely isolated object may simply recompute empty values.

See: recomputation-root decision.

Getter

A function or method used to produce the value returned by an attribute read.

In e-footprint: the decorated method is the domain getter. It receives self and computes a fresh value; the descriptor and slot add caching and dependency bookkeeping around it.

Getter closure

The zero-argument runtime function a ReactiveSlot calls to compute its value. It is a closure: a function that retains references to values from the surrounding scope where it was created. Here, those retained values include the original getter and the particular modeling-object instance.

In e-footprint: it calls the domain getter, attaches the result to its modeling-object address, and records calculus dependencies from the result's ancestry. An input or membership slot has no getter closure because it represents something that changes; it computes nothing.

Related: closure, ReactiveSlot.

Guard

A computed validation slot that must be pulled during an update so an invalid edit fails immediately and can be rolled back.

In e-footprint: a descriptor uses guard=True, or its name ends in _validation. Guards run even when they lie outside the requested eager-output cone.

Invalidation

Marking a cached result as no longer trustworthy, deleting that cached value, and propagating the same state to its transitive dependents.

In e-footprint: a deletion wave follows reverse slot edges. It preserves dependency topology so future changes can still cross currently void intermediate slots.

ReactiveSlot

The runtime node representing one stable modeling-object attribute address and its place in the recomputation graph.

In e-footprint: slots live in each object's _reactive_slots registry. A computed slot has a getter closure and may cache a result; an input or membership slot is getter-less and exists only as a stable invalidation source.

Related: getter closure, invalidation.

Read hook

A small bookkeeping call inserted into a normal attribute or collection access path so the engine can notice that the current computation consumed that relationship or membership.

In e-footprint: structural accessors such as ContextualModelingObjectAttribute.__getattr__ and ReverseCollection.__get__ call record_read_of_node(...). It does nothing outside a slot computation; during one, it adds the corresponding structural dependency to the top compute frame. The calculus-ancestry bridge has the same recording outcome but is not literally a per-read hook: it inspects the returned explainable value after the domain getter finishes.

Related: structural dependency, calculus dependency.

Structural dependency

A recomputation edge saying that a calculated attribute depended on which object a relationship pointed to, or which members a modeled collection contained.

In e-footprint: relationship and membership read hooks record these edges. Replacing pattern.country invalidates formulas that traversed that link even if the old and new countries expose similar values.

Contrasts with: calculus dependency.
