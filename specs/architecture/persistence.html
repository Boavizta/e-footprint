Architecture / Persistence

Persistence and partial computation

JSON persists domain inputs as truth, selected cached outputs as an optimization, and the graph topology needed to invalidate those outputs safely without rebuilding every intermediate.

Saving peeks, never pulls. A save cannot cause computation. If an edit voided a serializable slot, that value is simply omitted and will recompute when read. A boundary that requires a complete snapshot must explicitly call materialize_serialized_state before serialization; user-triggered download/export is the canonical example.
Canonical JSON only. The persistence API round-trips documents produced by system_to_json and transforms them through supported version migrations. Arbitrary externally authored or untrusted JSON is not supported: loading performs the structural checks required by this canonical format, not exhaustive schema or domain validation.

Minimal persistence contract (since v23)

One canonical system JSON
All object inputs
Authoritative model state and top-level Sources.
Selected cached slots
Only materialized serialize=True values, formulas, and ancestor addresses.
Values-free calculation graph
Every computing slot's calculus and structural dependency edges, slot addresses, and best-effort labels.

The selected values are each impact source's energy_footprint and instances_fabrication_footprint, System.total_footprint, the System.impact_repartition_matrix computed structure, and EdgeDevice.footprint_breakdown_summary. Children are derived by inversion at load. Anything absent is valueless and recomputes on read, making omission staleness-resilient by construction. system_to_json(system, save_computed_state=False) writes inputs only for lean committed fixtures and from-scratch rebuilds.

Why topology is stored even when intermediate values are not

A minimal file can load a cached total below void intermediate slots. An edit above those intermediates must still reach and delete the total. The values-free calculation_graph reinstalls both calculus and structural edges, allowing the deletion wave to traverse valueless nodes. See Recomputation lifecycle § deletion wave.

Version-aware loading

Saved versionWhat happens
Exact efootprint_version matchStored values attach as trusted slot caches and graph edges reinstall without computing. Later edits invalidate through the restored topology, structural edges included.
Any mismatchMajor-version schema handlers run. Surviving stored values become an in-memory, session-scoped “as computed by vX” baseline on each System; they are never re-serialized. System.compare_to_version_baseline() measures upgrade drift using standard comparison machinery.

The schema version is the major library version. The 22→23 handler drops legacy stored-computed entries. The 23→24 handler pluralizes web journeys at weight 1 and edge journeys as one-item lists, renames occurrence/deployment inputs, moves each edge journey's usage span onto its former pattern, and discards obsolete computed coordinates and graph state. version_upgrade_handlers.py owns schema migration logic; migrations apply to both inputs-only files and files carrying selected calculated state.

References and sources

json_to_system.py and system_to_json.py own the serialization round-trip.

Scalar-string object-reference heuristic

In ModelingObject.from_json_dict, a scalar string attribute is interpreted as an object reference when it equals an already-built object's id. id and name are exempt: names are labels, never references. Without that exemption, an object's name matching another object's id—for example a second “France” country beside a catalog object keyed France—would silently resolve to the object.

Source is top-level JSON state (since v21)

Each Source has a deterministic id: UUID in production, name-based in tests through Source._use_name_as_id. ExplainableObject.source serializes as "source": "<source_id>"; the top-level Sources block includes only referenced sources.

Sentinel ids user_data and hypothesis are pinned so Sources.USER_DATA and Sources.HYPOTHESIS re-identify with live Python singletons on reload. Source application is centralized in _apply_json_source in explainable_object_base_class.py; subclasses do not construct Sources in their own from_json_dict.

Form-built timeseries preserve authored state

Form-built hourly and recurrent quantities serialize their compact form_inputs instead of the derived array. The weekly-pattern recurrent builder retains every authored profile, including profiles assigned to no day, and recomposes its canonical 168-hour value during loading. Its unit + profiles matcher is distinct from the constant recurrent builder's constant_value + constant_unit matcher, so both shapes reload without a schema discriminator.
