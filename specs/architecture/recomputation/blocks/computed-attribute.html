@computed_attribute technical building block

One declaration plays two Python roles: decorator syntax replaces the getter with a descriptor on the class; the descriptor later routes every instance read to that instance's ReactiveSlot.

Keep the levels separate: one descriptor per declared class attribute; one computed slot and cached value per modeling-object instance.

Three objects, three jobs

ObjectCreated whenResponsibility
Getter functionPython executes the def statement inside the class body.The domain formula. It takes self and returns a fresh computed value.
computed_attribute descriptorPython applies the decorator while building the class namespace.Retains the getter, documentation, serialize/guard flags, and controls attribute access through __get__.
ReactiveSlotThe descriptor is first read for a particular instance.Stores that instance's cached/void state, getter closure, dependency edges, dependents, and wave marker.

How decorator syntax installs the descriptor

Written

class UsagePattern(ModelingObject):
    @computed_attribute
    def utc_hourly_usage_journey_starts(self):
        return ...

Conceptual expansion

class UsagePattern(ModelingObject):
    def utc_hourly_usage_journey_starts(self):
        return ...

    utc_hourly_usage_journey_starts = computed_attribute(
        utc_hourly_usage_journey_starts
    )
Class-body execution order
1 · def creates a function
The function is temporarily bound to utc_hourly_usage_journey_starts in the class namespace under construction.
↓ Python evaluates and applies the decorator
2 · computed_attribute(function) returns a descriptor
__init__ calls _bind_getter, retaining the original function and its docstring.
↓ Python rebinds the same class-namespace name to the returned object
3 · type creates UsagePattern
The finished class dictionary contains the descriptor, not the original bare function.
↓ Python's descriptor setup hook
4 · descriptor.__set_name__(UsagePattern, "utc_hourly_usage_journey_starts")
It verifies the getter/name match and registers the declaration in _declared_computed_slots.

The decorator does not explicitly call setattr(UsagePattern, ...). Python stores whatever the decorator returns under the function's name while it is still assembling the class namespace.

Parameterized decorator form

@computed_attribute(serialize=True, guard=True) has one extra call because the parentheses make Python evaluate the decorator expression before it applies the decorator to the function. The first call receives configuration options—not the getter—so it creates a configured but getter-less descriptor. Python must then make a second call to pass the newly created getter function to that descriptor; computed_attribute.__call__ binds it.

Without options · one call

@computed_attribute
def value(self): ...

# Conceptually:
value = computed_attribute(value)

The getter is supplied directly to the descriptor constructor.

With options · two calls

@computed_attribute(serialize=True, guard=True)
def value(self): ...

# Conceptually:
decorator = computed_attribute(
    serialize=True, guard=True
)
value = decorator(value)

The first call supplies options; the second supplies the getter.

# Conceptual expansion of @computed_attribute(serialize=True)
decorator = computed_attribute(serialize=True)  # getter is not bound yet
descriptor = decorator(utc_hourly_usage_journey_starts)
# descriptor.__call__ binds the getter and returns descriptor itself

utc_hourly_usage_journey_starts = descriptor
OptionIndependent responsibility
serialize=TruePersist the cached value when materialized.
guard=TruePull after invalidation so intentional validation failures reject the update.
purposes={ComputationPurpose.FOOTPRINT}Mark a meaningful footprint output root. Intermediate footprint membership is derived from the materialized dependency graph, not copied onto each descriptor.

How the installed descriptor handles reads

Class read
UsagePattern.utc_hourly_usage_journey_starts
Python calls __get__(None, UsagePattern); the descriptor returns itself. Documentation and registry code inspect this form.
Instance read
pattern.utc_hourly_usage_journey_starts
Python calls __get__(pattern, UsagePattern); the descriptor resolves and pulls the instance slot.
First instance read
computed_attribute.__get__
Calls self.slot(pattern).
↓
slot(pattern)
Looks in pattern.__dict__["_reactive_slots"]. If absent, creates a ReactiveSlot and gives it a closure around self.getter(pattern).
↓
slot.pull()
Returns the cached value or runs the closure, records dependencies, and caches the fresh result.

The getter closure closes the loop

ReactiveSlot._compute() first pushes that slot's compute frame, then calls the zero-argument closure stored in slot.getter. The closure runs the domain getter and explicitly bridges its returned ExplainableObject ancestry into the active frame:

def compute():
    # 1. Run the original decorated domain getter for this instance.
    #    Relationship wrappers record structural reads while it runs.
    value = self.getter(instance)

    # 2. Attach the result to this modeling-object attribute and slot.
    self._attach_to_owner(instance, value, slot)

    # 3. Map the result's explainable ancestors back to their slots.
    #    record_calculus_dependency(...) adds each slot to the active
    #    frame's calculus_reads set through the compute stack.
    record_calculus_edges_from_ancestry(value)

    return value
This is the handoff: the domain getter creates the value and its formula ancestry; the closure turns that ancestry into slot-level calculus dependencies; ReactiveSlot._compute() then commits the frame's calculus and structural sets. See ReactiveSlot § how read hooks mutate the active frame.

record_calculus_edges_from_value_structure(value) is the corresponding bridge for @lazy_attribute, whose result may be a nested raw dict/list/dataclass containing explainables. A normal @computed_attribute uses record_calculus_edges_from_ancestry(value).

“Class-level descriptor” does not mean “class-level cache.” The class shares computation behavior; instances never share computed slot state.

Writes and deletes

  • A normal assignment to a computed attribute is rejected by ModelingObject.__setattr__; callers must change its inputs.
  • The trusted JSON load path uses the descriptor's explicit attach_cached_value(instance, value) hook.
  • Deleting the computed attribute calls __delete__, drops the slot's cached value, and lets the next read recompute it.
Read the implementation in this order
  1. computed_attribute.__init__, _bind_getter, and __call__ — decorator construction.
  2. computed_attribute.__set_name__ — class registration.
  3. computed_attribute.__get__, slot, and _make_compute_closure — instance dispatch.
  4. ReactiveSlot.pull and _compute — runtime computation and caching.
  5. ModelingObject.__setattr__ — the public assignment guard.
