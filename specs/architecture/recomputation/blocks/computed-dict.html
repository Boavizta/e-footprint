@computed_dict technical building block

A computed dict is not one cached dictionary calculation. It is a stable facade over a key-set slot and one independently reactive calculation per current key.

Shortest useful model: the key-set slot owns membership and synchronization; each element slot owns one value, getter execution, dependency set, and cache.

What the declaration creates

@computed_dict(keys="jobs")
def energy_footprint_per_job(self, job):
    return self.compute_energy_for(job)

Why the facade persists: downstream code may keep a reference to the returned mapping. Recomputing replaces element caches and synchronizes entries without replacing the facade object itself.

What happens on a whole-dict read

  1. computed_dict.__get__ resolves the owner's key-set slot.
  2. If another computation is active, reading the whole dict records a structural dependency on that key-set slot: the consumer depends on which keys exist.
  3. slot.pull() returns the cached facade or invokes the key-set closure.
  4. The closure reads getattr(instance, keys), drops stale keys, pulls one sub-slot per current key, restores collection order, and returns the same facade.
  5. Each element closure calls getter(instance, key), attaches the fresh value into the facade, and records calculus dependencies from that value's formula ancestry.

Why element slots matter

Fine-grained invalidation
If only job B's consumed inputs change, B's element slot becomes void while A's cached value remains reusable.
Whole-dict dependency
A consumer that reads the facade as a collection also depends structurally on the key-set node, so membership changes invalidate that consumer.

After invalidation, prune_stale_computed_dict_keys() synchronizes membership before the transaction pulls guards or an ordinary output. It clears the guard flag on departed sub-slots so the guard pass, which still holds the pre-pruning invalidation set, skips them. See how an update chooses its recomputation root.

When a key leaves

  1. discard_stale_keys() removes the composite-key sub-slot from the owner's registry and clears its guard policy.
  2. The corresponding facade entry is dropped passively, without starting another modeling update.
  3. Previously computed dependents retain their old dependency edge to the removed sub-slot until they successfully recompute. That edge remains available to invalidation traversal but never pulls the removed sub-slot.
  4. prune_stale_computed_dict_keys() performs membership cleanup after invalidation even when nobody reads the facade, preventing detached objects from remaining reachable through stale container bookkeeping.

Guards and persistence

guard=True marks the key-set node and every element slot as validation guards. serialize=True persists materialized entries under the minimal calculated-state contract. peek() returns the facade only when the key-set slot and every current element slot are cached; it never exposes stale facade entries as current state.

Read the implementation in this order
  1. computed_dict.slot, facade, and __get__ — key-set access and stable facade.
  2. sub_slot and _make_element_compute_closure — per-key calculation.
  3. discard_stale_keys and prune_stale_computed_dict_keys — safe membership removal.
