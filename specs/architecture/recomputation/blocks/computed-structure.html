@computed_structure technical building block

A computed structure caches one arbitrary raw or nested result in the same reactive graph as every other computed surface.

The name describes shape, not timing. All three surfaces are pull-based. This surface is distinct because one slot owns the entire recursively inspected result.

Bare and parameterized forms

@computed_structure
def impact_repartition_rows(self):
    return tuple(self.build_rows())

A bare descriptor receives and binds the getter immediately.

@computed_structure(serialize=True)
def impact_repartition_matrix(self):
    return tuple(self.build_matrix())

The first call creates an unbound descriptor carrying configuration; decorator application then calls that descriptor with the getter.

In both forms, __set_name__ registers the descriptor in the class's computed-structure registry. Structures are excluded from calculated_attributes because their raw results are not attached explainable attributes.

What “raw” means

Computed attributes
Return a fresh explainable value. The closure attaches it to the owner/address and writes the slot backpointer.
Computed structures
May return a plain dict, tuple, list, set, dataclass, scalar, explainable, or a nested combination. The slot owns the cache directly.

Raw does not mean dependency-free. It means the structure is not part of the modeling object's explainable-container ownership structure.

How a nested result records dependencies

def compute():
    value = self.getter(instance)
    record_calculus_edges_from_value_structure(value)
    return value
Recursive value-structure walk
Existing modeled explainable
Record the slot of the modeled attribute it belongs to.
Fresh derived explainable
It has no slot of its own; record the slots of its nearest modeled formula ancestors.
Container/dataclass
Visit dict values, sequence/set items, or dataclass fields recursively.

This extra walk matters because structure code often reduces explainables into raw rows or containers. Without it, dependencies carried only by arithmetic ancestry could disappear when the return value is no longer one attached explainable object.

When structure code reduces to plain scalars early

If a getter extracts a magnitude or otherwise destroys an explainable's ancestry before placing the result in its return structure, it must call record_calculus_edges_from_ancestry(explainable) before that reduction. impact_repartition_rows does this for each atom's hourly value before converting it to a period-total scalar.

When one computed structure reads another

When an outer structure getter reads an inner computed structure, computed_structure.__get__ records a dependency on the inner slot before pulling it. The outer slot therefore depends directly on the inner structure; the inner structure keeps its own internal dependencies.

Pull behavior

After invalidation
The cached raw value is dropped and stays void until read, like any ordinary non-guard computed slot.
At consumption time
The reader pulls it only if that consumer needs it. Serialization only peeks and never pulls.

Explicit cache lifetime

transient=True marks a runtime-only intermediate whose owning calculation may release its cached value after reducing it. evict_transient_structures(instance) drops each materialized transient structure on that instance without invalidating or removing graph edges: an already-cached descendant remains readable, while a later input edit still reaches and invalidates that descendant through the void intermediate.

Transient structures cannot also declare serialize=True. Their raw contents are not attached to modeling-container bookkeeping, so eviction only releases the slot's strong reference; it does not detach nested explainables or alter explanations.

Optional persistence

By default, computed structures are runtime-only. serialize=True opts a materialized cache into the minimal persistence contract:

  • peek() returns the cached raw value without computing; an unread or invalidated slot is simply omitted on save.
  • The value must be JSON-native because it bypasses explainable serialization machinery.
  • Loading calls attach_cached_value() to seed the slot without running the getter.
  • Serialized dependency topology still determines which edits invalidate that loaded cache.

Writes are rejected

The descriptor defines __set__ and raises AttributeError. A computed structure is derived state; callers change its inputs and let invalidation/recomputation update it.

Read the implementation in this order
  1. computed_structure.__init__, __call__, and __set_name__ — both decorator forms and registration.
  2. slot, __get__, and _make_compute_closure — per-instance dispatch and caching.
  3. record_calculus_edges_from_value_structure — recursive dependency discovery.
