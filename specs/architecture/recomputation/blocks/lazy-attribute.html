@lazy_attribute technical building block

A lazy attribute is a cached reactive projection: it uses the same slot graph as core calculations but stays outside eager calculated state and keeps its result raw.

“Lazy” changes pull policy, not correctness. The slot still discovers dependencies, caches success, becomes void after relevant edits, and recomputes on its next explicit read.

Bare and parameterized forms

@lazy_attribute
def impact_repartition_rows(self):
    return tuple(self.build_rows())

A bare descriptor receives and binds the getter immediately.

@lazy_attribute(serialize=True)
def impact_repartition_matrix(self):
    return tuple(self.build_matrix())

The first call creates an unbound descriptor carrying configuration; decorator application then calls that descriptor with the getter.

In both forms, __set_name__ registers the descriptor in the class's lazy-slot registry. Lazy slots are deliberately excluded from calculated_attributes and computed-attribute reference documentation.

What “raw” means

Computed attributes
Return a fresh explainable value. The closure attaches it to the owner/address and writes the slot backpointer.
Lazy attributes
May return a plain dict, tuple, list, set, dataclass, scalar, explainable, or a nested combination. The slot owns the cache directly.

Raw does not mean dependency-free. It means the projection is not part of the modeling object's explainable-container ownership structure.

How a nested result records dependencies

def compute():
    value = self.getter(instance)
    record_calculus_edges_from_value_structure(value)
    return value
Recursive value-structure walk
Attached explainable
Record its own _reactive_slot.
Unattached explainable
Record the slots of its nearest attached formula ancestors.
Container/dataclass
Visit dict values, sequence/set items, or dataclass fields recursively.

This extra walk matters because projection code often reduces explainables into raw rows or containers. Without it, dependencies carried only by arithmetic ancestry could disappear when the return value is no longer one attached explainable object.

When projection code reduces to plain scalars early

If a getter extracts a magnitude or otherwise destroys an explainable's ancestry before placing the result in its return structure, it must call record_calculus_edges_from_ancestry(explainable) before that reduction. impact_repartition_rows does this for each atom's hourly value before converting it to a period-total scalar.

When another computation reads a lazy slot

If a computation is already active, lazy_attribute.__get__ calls record_calculus_dependency(lazy_slot) before pulling it. The outer slot therefore depends directly on the projection slot; the projection keeps its own internal dependencies.

Why it never warms eagerly

After invalidation
The cached raw value is dropped and the slot remains void. System-total pulls and ordinary eager sweeps skip it.
At consumption time
A renderer, attribution fold, or other explicit attribute reader pulls it only if that consumer actually needs it. Serialization only peeks and never pulls.

This keeps attribution and presentation work out of the main footprint update path while preserving exact invalidation when their inputs change.

Optional persistence

By default, lazy projections are runtime-only. serialize=True opts a materialized cache into the minimal persistence contract:

  • peek() returns the cached raw value without computing; an unread or invalidated slot is simply omitted on save.
  • The value must be JSON-native because it bypasses explainable serialization machinery.
  • Loading calls attach_cached_value() to seed the slot without running the getter.
  • Serialized dependency topology still determines which edits invalidate that loaded cache.

Writes are rejected

The descriptor defines __set__ and raises AttributeError. A lazy projection is derived state; callers change its inputs and let invalidation/recomputation update it.

Read the implementation in this order
  1. lazy_attribute.__init__, __call__, and __set_name__ — both decorator forms and registration.
  2. slot, __get__, and _make_compute_closure — per-instance dispatch and caching.
  3. record_calculus_edges_from_value_structure — recursive dependency discovery.
