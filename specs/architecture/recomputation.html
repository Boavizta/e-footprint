Architecture / Recomputation engine

Pull-based recomputation engine

A computed value is a cached node, not a step in a global schedule. Reads recursively pull what is missing. Writes delete only the affected cache cone, then deliberately pull the outputs that must fail fast.

The central mental model: formulas define nodes; successful reads discover edges; edits send a deletion wave forward through those edges; the next pull rebuilds exactly what is needed.

One real getter, two edge kinds

The distinction is about what the formula depends on: values create calculus edges; object links and collection memberships create structural edges. The same getter commonly creates both.

Abridged from UsagePattern.utc_hourly_usage_journey_starts
@computed_attribute
def utc_hourly_usage_journey_starts(self):
    converted = self.hourly_usage_journey_starts.convert_to_utc(
        local_timezone=self.country.timezone
    )
    return converted.set_label("Hourly journey starts (UTC)")
Calculus edges — values used
hourly_usage_journey_starts → result
country.timezone → result
Changing either value invalidates the result.
Structural edge — relationship used
self.country link → result
Replacing France with Japan invalidates the result, even before considering their timezone values.
Why reading self.country.timezone creates both kinds: the computation depends on which country the link points to (structural), and on that country's timezone value (calculus). Both edges point to the computed utc_hourly_usage_journey_starts slot and both trigger the same invalidation behavior.
Implementation detail: what “getter-less node” or “bump node” means

The graph needs a stable internal identity for each input value and relationship membership so computed slots can list it as a dependency. That identity is represented by a ReactiveSlot with no getter: it computes nothing and holds no derived value. A write “bumps” it by launching invalidation into its dependents.

This is storage machinery, not a third conceptual dependency kind. At the modeling level, think only in terms of value/calculus dependencies and relationship/structural dependencies.

Building block: @computed_attribute

The decorator turns a getter function into a class-level descriptor; instance reads then route through that descriptor to a per-instance reactive slot. It declares the computation without running it during construction.

1 · First access creates and computes the output slot

starts_utc = pattern.utc_hourly_usage_journey_starts
  1. computed_attribute.__get__ calls slot(pattern). It creates a computing ReactiveSlot under pattern._reactive_slots["utc_hourly_usage_journey_starts"], installs a closure around the domain getter, then calls pull().
  2. The slot is void, so ReactiveSlot._compute() pushes a temporary compute frame onto the context-local stack. That frame has two initially empty sets: calculus_reads and structural_reads.
  3. The getter reads self.country.timezone. Access passes through ContextualModelingObjectAttribute.__getattr__, which calls record_read_of_node(pattern, "country"). This lazily creates the getter-less pattern._reactive_slots["country"] node and puts it in the frame's structural_reads.
  4. convert_to_utc() returns a new explainable value whose direct arithmetic ancestors are the hourly-start input and the Country's timezone value.
  5. The descriptor's compute closure attaches that result to (pattern, "utc_hourly_usage_journey_starts") and sets the result's _reactive_slot backpointer to the computing slot.
  6. record_calculus_edges_from_ancestry(result) maps the two explainable ancestors to stable attribute-address nodes through slot_of_attached_value(): pattern._reactive_slots["hourly_usage_journey_starts"] and country._reactive_slots["timezone"]. Both getter-less nodes enter calculus_reads.
  7. On successful return, ReactiveSlot.replace_dependencies() replaces the computing slot's old dependency sets and adds the computing slot to each input node's reverse _dependents set. attach_cached_value() then stores the result in the computing slot's _value.

Two graphs coexist. The computed explainable value still stores its formula ancestry for explanation. The slot stores attribute-address dependencies and reverse dependents for cache invalidation. The descriptor's compute closure is the bridge between them.

3 · Numerical input change follows the calculus edge

pattern.hourly_usage_journey_starts = revised_starts
  1. Because live updates are enabled, ModelingObject.__setattr__ creates a ModelingUpdate containing the old attached input and the new value.
  2. Before replacing anything, slot_of_attached_value(old_starts) follows the old value's backpointer and captures S_starts as the changed node.
  3. apply_changes() detaches the old input and attaches revised_starts at the same (pattern, attribute) address. Detaching clears the old value's backpointer; the stable S_starts node itself remains in pattern._reactive_slots.
  4. invalidate(S_starts) marks S_starts, follows S_starts._dependents to S_utc, and drops S_utc._value. The drop callback unlinks the obsolete computed explainable from pattern. Dependency sets remain in place so later waves can still cross void slots.
# State at the end of the deletion wave, before any eager pull
S_starts._wave_passed is True
S_utc._wave_passed is True
S_utc.has_cached_value is False
S_utc._calculus_dependencies == {S_starts, S_timezone}  # topology retained
  1. ModelingUpdate.pull_eagerly() pulls guards and then the requested boundary: normally System.total_footprint; an explicit eager_outputs=() leaves S_utc void until a later read.
  2. When S_utc is pulled again, the getter uses revised_starts. slot_of_attached_value(revised_starts) resolves its attribute address back to the existing S_starts node and writes that backpointer onto the new value.
  3. The successful computation atomically refreshes both edge sets, caches a fresh result, and clears wave markers on the dependencies and output. Nothing retains the old computed value.

4 · Relationship change follows the structural edge—and rewires calculus

pattern.country = japan
  1. ModelingUpdate.parse_changes_list() wraps Japan in a new ContextualModelingObjectAttribute. The old Country wrapper resolves to the stable S_country_link node for (pattern, "country").
  2. apply_changes() detaches the France wrapper and attaches the Japan wrapper. The wrapper's container transition also bumps affected reverse-relationship nodes; the explicit changed node here is still S_country_link.
  3. invalidate(S_country_link) follows its structural dependent to S_utc and drops the cached UTC series exactly as in the numerical-input case.
  4. On recomputation, reading self.country.timezone records the same stable structural dependency on S_country_link, but the returned timezone now belongs to Japan.
  5. replace_dependencies() removes S_utc from France's timezone node, adds it to Japan's timezone node, and replaces the calculus set with {S_starts, S_japan_timezone}. Future edits to France no longer invalidate this pattern; edits to Japan do.

If the relationship stays unchanged and only country.timezone changes, the calculus edge from that Country's timezone node invalidates S_utc directly. This is why self.country.timezone creates both edge kinds.

Deletion wave and partial state

ModelingObject.__setattr__ routes live writes through ModelingUpdate, which normalizes list, dict, and modeling-object links and skips equal changes before applying relationship bookkeeping. The walkthrough above follows both a numerical edit and a relationship edit through that transaction.

Void intermediate
May already have no cached value after a minimal reload.
↓ wave must continue
Cached serialized output
Must be dropped or it becomes stale.
Wave marker, not voidness
A marked slot means its dependents have already been marked by this or an earlier sound wave. A fresh dependent cache can only arise after pulling through the dependency, which clears the marker.

invalidate(*slots) deletes cached values from changed slots and every transitive dependent. Its one-bit wave_passed marker prunes repeated traversal. A void slot cannot prune: the normal persisted shape can have cached outputs below valueless intermediates. This is why the serialized dependency topology matters; see Persistence.

Guards: constraints that must fail at edit time

A slot is a guard when its name ends in _validation or its descriptor declares guard=True. Guards cover user-facing constraints that may sit outside the system-total footprint cone, such as edge-capacity checks. Every invalidated guard is pulled regardless of eager_outputs.

New-link edge case: a never-computed guard has no recorded dependency edge, so a deletion wave cannot reach it. ModelingUpdate explicitly finds every newly linked object and its linked subtree and pulls all of their guards. Invalid new links are therefore rejected immediately.
Which values are pulled after invalidation?

Computation remains pull-based: the “eager” phase only chooses which observable boundaries are deliberately read after invalidation. eager_outputs is a collection of (modeling object, attribute name) pairs. With the default None, the affected system's total_footprint is pulled so errors in the changed footprint cone surface during the transaction. Tight loops pass eager_outputs=() and leave ordinary invalidated values void until their next read.

If changed objects belong to no system, the update pulls the invalidated cone because there is no system-total boundary through which errors could surface and detached subgraphs are small. Lazy slots are never part of eager sweeps: attribution projections remain void until a render or explicit read asks for them.

Where dependency edges come from

KindRecorded whenSource
CalculusA computed value's arithmetic ancestry contains an attached explainable value—or a lazy projection returns a structure containing one.ExplainableObject ancestry → record_calculus_dependency.
StructuralA getter reads an input node, direct/list/dict membership, reverse relationship, or modeling-container relationship.Relationship/input read hooks → record_structural_dependency.

Membership writes also bump affected reverse-relationship nodes at the container-field transition. All dependencies live in this one slot-addressed graph; there is no global computation order and no wholesale cache flush.

Correctness invariants

  • Edges describe real reads. Wave pruning is sound only because recorded edges come from values or relationships the computation actually consumed.
  • Edges refresh atomically on success. A changed conditional branch cannot retain an obsolete dependency forever.
  • Failure favors over-invalidation. Previous edges survive a failed getter; its value does not.
  • Marked implies dependents marked. This—not cached/void state—is the deletion-wave pruning invariant.
  • Getters are read-only. Writes during computation are rejected.
  • Framework stays domain-blind. Eager behavior is configured structurally through outputs and guards, never by naming core classes.
  • Rollback is transactional. A rejected update restores original inputs/links, invalidates the failed state, and pulls the restored eager boundary.
