Attribution: the atom model

Every explanation starts from the same finest-grained slices and differs only by filtering and grouping. Attribution is an on-demand downstream computation: footprint formulas never depend on attribution results.

Conservation by construction: the sum of a stream's atoms equals that stream's footprint, which equals the eager totals. Renderers group atoms; they do not invent or rescale footprint.

Attribution lives entirely in efootprint/core/attribution/. Calculated attributes never read attribution results—the one-way rule that keeps this projection layer strictly downstream of the footprint graph. Each source decomposes its footprint exactly once into atoms; every attribution number is a fold over them.

JobOccurrenceCoordinate is the reusable calculation address below those cells: (usage pattern, web step) or (edge usage pattern, recurrent server need). Per-coordinate computed dicts cache duration-averaged occurrences and transferred data; both Job.attribution_cells and Network.attribution_atoms read them. An edge cell applies its EdgeFunction multiplicity afterward, so two functions reaching the same need do not duplicate the base calculation.

ImpactRepartitionSankey is presentation-only. It makes one node_totals_and_links_by_phase_in_kg call and owns layout, colors, and aggregation—not footprint logic. The fold normalizes contextual relationship wrappers and class visibility once, then groups every requested lifecycle phase in one matrix pass. Its build path keeps the stored matrix's canonical period-total kg scalars as floats, including breakdown normalization; Pint is introduced only at the final display-unit formatting boundary. The general node_totals_and_links surface remains quantity-valued for programmatic callers. footprint_per_node and footprint_per_node_per_source remain hourly reads that fold live atoms on every call.

Each AttributionSource mixin exposes impact_repartition_rows: rows keyed by (source, stream, cell coordinate ids, up, phase) with a period sum in kg. Calculus edges are recorded from each atom's hourly value before reduction. System.impact_repartition_matrix concatenates one source's rows, then evicts that source's transient attribution-only hourly helpers before moving to the next source. The rows stay cached and their preserved graph edges still invalidate them after later input edits.

Precise invalidation and serialized computed structures

Coupled per-source share physics such as binding_demand_per_job, attribution_cells, and retention_cumulative_per_cell uses @computed_structure: the whole raw or nested result computes, caches, and invalidates as one unit through recorded dependency edges.

The matrix and each edge device's period-summed footprint_breakdown_summary are @computed_structure(serialize=True). Once a Sankey materializes them, a same-version loaded session can render every Sankey combination from stored data.

impact_repartition_rows_cache_coverage(system) reports (cached source slots, total source slots) for exactly the attribution sources required by the system matrix. It unwraps contextual relationship proxies and uses each source descriptor's peek surface, so asking for coverage never creates or computes a missing row slot. This is source-slot coverage only: sources can differ substantially in work and retained memory.

EdgeDevice booking rule

Fabrication is deployment-booked; energy is need-booked. A deployed but unused component still embodies carbon. It consumes no operational energy without a need.
Unused components, chassis shares, and RecurrentServerNeed-only patterns

A component with no needs in a pattern served by the device still books its fabrication eagerly with deployment, like the chassis. EdgeDevice.unused_component_fabrication_per_edge_device derives this from component input attributes because need-less components never enter the calculated-attribute chain. Thus eager per-pattern fabrication totals carry the whole device.

For attribution, that unused-component pool—its own fabrication plus equal chassis shares—splits equally across the pattern's deployment carriers: component needs and RecurrentServerNeeds. A recurrent-server-need-only pattern therefore routes the whole device fabrication through those needs. A pattern with booked fabrication and no carriers raises. Energy has no equivalent rule: unused components draw nothing and book no energy on either side.

Public convenience surface

attribution.attributed_footprint(obj, phase) is the targeted on-demand read: it streams live atoms in source order and accumulates only those attributed to the requested object at its own class level, summed across its systems (Empty when system-less). After each source it materializes the running result's formula, releases its arithmetic value-parent tree, and evicts that source's transient helpers; later sources remain composable into the complete explanation without changing numerical addition order. Use footprint_per_node or footprint_per_node_per_source when a caller genuinely needs batch totals for every node at a level. None of these hourly reads cache atoms or attributed outputs.
