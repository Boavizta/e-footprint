Comparison & display boundaries

Comparison is domain-truth read logic over already-computed systems. Display is the only place that rescales Pint values for human readability.

No new modeling claims: comparison derives from system totals and declared inputs; it does not add footprint or attribution logic.

Outputs and their invariants
  • Totals + delta come from total_footprint.sum(). Delta exposes absolute change and the relative fraction over baseline, or None when baseline is zero.
  • Per-(category, phase) decomposition reads each system's total_energy_footprint_sum_over_period and total_fabrication_footprint_sum_over_period dictionaries. OBJECT_CATEGORIES is category SSOT. Because those dicts sum to the total, rows sum to the headline delta.
  • Aligned + cumulative time-series share a calendar axis through align_temporally_quantity_arrays, zero-padding non-overlapping hours. TimeSeries carries the usage_*/fabrication_* phase splits on that same axis, summed exactly as total_footprint does, so usage + fabrication reconstructs every hour and consumers can bucket phase splits per period.
  • Notebook plots—plot_emissions_over_time, plot_cumulative_emissions, and plot_decomposition—reuse matplotlib.
Input diff: identity pairing, positive input detection, and relationship rules

The diff walks all_linked_objects, pairs by id first and then by (name, type), and emits changed input rows plus objects only in A or B. Inputs are identified positively from get_init_signature_params(efootprint_class), the same constructor-signature SSOT as copy_with, rather than by excluding calculated attributes. Reading efootprint_class rather than type(obj) sees through ContextualModelingObjectAttribute.

Scalar/array explainables diff by value, unit, source, and confidence. If both are form-built timeseries exposing form_inputs_for_display—ExplainableHourlyQuantitiesFromFormInputs or ExplainableRecurrentQuantitiesFromConstant—their human parameters are compared instead, for example “net growth rate: 10 % per year → 20 %”, listing only changed parameters and avoiding opaque array diffs.

ExplainableObjectDict and List[ModelingObject] inputs diff by membership (per-key counts or presence), pairing elements by the same id-first rule. An add/remove membership row is emitted only when the member exists in both models, meaning a true re-link. An object present in one model only remains solely in the “only in A/B” row and is not duplicated.

Duplication for meaningful comparison

efootprint/comparison/duplication.py provides duplicate_system(system): serialize→deserialize while minting a fresh System id and preserving every contained object id, allowing identity pairing. assign_fresh_system_id(system) re-ids only the System. The new id is distinct even under name-as-id test conventions.

Units and display

All quantities use Pint; custom units live in efootprint/constants/custom_units.txt. Calculations preserve Pint quantities unchanged and remain explainable through their dependency graphs.

Render-time scaling only. efootprint/utils/display.py owns best_display_unit() and format_quantity_for_display(). Explainable classes expose display_quantity and display_unit; computation never substitutes display-scaled values.
