Delta-encoded hourly timeseries — Backlog analysis

Status: Parked backlog · 2026-08-31

1. Decision

Do not implement now. Delta encoding has negligible typical-case benefit in the representative corpus, but is an effective escape hatch if smooth growth-based timeseries repeatedly make serialized models exceed their payload budget.

The current codec converts hourly values to float32, compresses their raw bytes with Zstandard, and Base64-encodes the result. Constant and repetitive arrays already compress exceptionally well. Smooth but continually changing aggregates can contain tens of thousands of distinct floating-point values and compress poorly.

2. Proposed transform

  1. View each float32 bit pattern as an unsigned 32-bit integer.
  2. Store the first word followed by wrapping unsigned differences between consecutive words.
  3. Compress the delta words with the existing Zstandard/Base64 pipeline.
  4. Reconstruct with an unsigned cumulative sum and view the recovered words as float32.

This is bit-exact, including negative zero, infinities, and NaN payloads. Arithmetic float deltas are not suitable: cumulative floating-point rounding failed the bit-exact proof of concept. XOR deltas and byte shuffling were also measured and compressed the stress model less effectively.

If introduced with a new JSON major version, prefer the self-describing key delta_compressed_values. Existing compressed_values remains the legacy raw-float codec. This avoids a separate encoding field while allowing standalone nested timeseries to decode without top-level version context.

The representative corpus result is intentionally based on normalized current-schema payloads, not the old files' on-disk bytes: each source file is upgraded through the real interface importer and every serialized computed slot is materialized before measurement. Universal delta made a few tiny files up to 0.29% larger. Adaptive selection removes regressions but requires either compressing twice or a reliable selection heuristic.

The stress model contains 160 arrays covering 49.651 MB of raw float32 data. Its aggregate impact-source series combine three years of growing starts with a five-year usage span, producing roughly eight-year per-pattern footprints and a nine-calendar-year aggregate. About 52,500 of 78,839 aggregate values are distinct, which defeats the current raw-byte compression but responds well to bit-pattern deltas.

5. Implementation and risks

  • Change ExplainableHourlyQuantities.to_json and lazy decompression to write/read delta_compressed_values; retain legacy compressed_values loading.
  • Define byte order explicitly and validate that decompressed buffers contain complete 32-bit words.
  • Re-encode legacy compressed values when writing the new major format. The current lazy pass-through path would otherwise preserve old raw strings indefinitely.
  • Add bit-exact round trips for random values, negative zero, infinities, and NaNs; add legacy-load and malformed payload tests.
  • Pin a growth-heavy size regression fixture. The existing representative corpus alone would not detect the pathological improvement this proposal targets.
  • If adaptive selection is desired, benchmark its doubled compression work or implement and validate a cheap entropy heuristic before adopting it.

Expected production scope is approximately 30–50 lines plus tests and persistence documentation.

6. Reproduction

Run from the interface Poetry environment so the script can normalize old files through the real importer:

cd e-footprint-interface
poetry run python ../e-footprint/specs/backlog/delta-timeseries-encoding/benchmark.py \
  ../json_files_that_should_load_and_open_results_without_failing_in_interface

# Add the growth-heavy export and repeat the timing microbenchmark:
poetry run python ../e-footprint/specs/backlog/delta-timeseries-encoding/benchmark.py \
  ../json_files_that_should_load_and_open_results_without_failing_in_interface \
  --stress-json "/path/to/growth-heavy-model.e-f.json" --timings

The private corpus is not committed. The script redacts filenames by default, verifies every delta round trip, and prints current, universal-delta, and adaptive compact sizes. Normalization may call model-owned external providers if an old fixture lacks cached provider results; use the same dependency versions and API cache when reproducing a release decision.

7. Activation criterion

Reconsider this work if growth-based or otherwise smooth high-entropy hourly aggregates repeatedly approach the interface payload limit, or if serialized timeseries become a measured storage/network bottleneck. Re-run the corpus and a current failing stress model before implementation because serialization policy and workload shape may change.
