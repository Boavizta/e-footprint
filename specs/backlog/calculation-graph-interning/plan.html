Calculation-graph object/attribute interning — Backlog plan

Status: Parked backlog · 2026-08-05

1. Decision context

The v23 calculation graph repeats object IDs and attribute names in node addresses. Graph-local lookup tables can replace those strings with integer indices while leaving edge indices and labels unchanged.

This is the best broad optimization for logical JSON, but not for the interface's Redis hot path. Django stores a pickled dictionary and pickle already memoizes repeated strings. Do not prioritize this work on the claim that it saves 9% of Redis memory.
Canonical 13-model corpusMeasured value
Calculation graph share of logical JSON31.5% weighted; 42.5% median; 2.7–62.0% range

JSON codec effectEncode 2.62 → 2.43 ms; decode 14.69 → 14.11 ms across all 13 models
Pickle codec effectApproximately neutral within benchmark noise

2. Proposed wire format

Keep the graph self-contained and deterministic:

{
  "objects": ["object-id-0", "object-id-1"],
  "attributes": ["total_footprint", "energy_footprint"],
  "nodes": [[0, 0, null], [1, 1, 0]],
  "edges": [...],
  "labels": {...}
}

Object and attribute tables follow deterministic first occurrence in the already deterministically sorted node sequence. A dict maps each value to its index while the graph is generated, so there is no post-serialization pass.

3. Implementation outline

  1. Change calculation_graph_section to emit graph-local object/attribute tables and integer-addressed nodes directly.
  2. Change rebuild_dependency_graph to resolve the indices inline while materializing slots; do not allocate a temporary expanded node list.
  3. Use the next available JSON major schema version and add the required migration behavior. Since mismatched stored computed state is demoted rather than trusted, avoid preserving obsolete graph topology unnecessarily.
  4. Update deterministic serialization, corrupted-index, exact-version cache restoration, invalidation, and randomized mutation-parity tests.
  5. Update specs/architecture/persistence.html, changelog, and performance baselines.

4. Complexity and risks

  • Complexity: medium—roughly 60–100 production lines plus migration, tests, and documentation.
  • Hot path: direct table construction adds hash lookups during save; direct table lookup adds two or three list reads per node during load. The smaller JSON offsets this for JSON consumers, while pickle should remain neutral. Performance gates are mandatory.
  • Corruption diagnostics: invalid object, attribute, or key indices must raise an address-specific error rather than leaking IndexError.
  • Readability: graph nodes become less manually readable, although graph edges are already indexed and this section is machine topology rather than user-authored input.

5. Activation criterion

Promote this backlog item when logical JSON quota/export size is again a priority, when the Redis serializer moves from pickle to JSON, or when graph growth itself becomes a measured cache/network bottleneck. Re-run the canonical corpus before planning implementation because graph shape and serialization policy may have changed.
