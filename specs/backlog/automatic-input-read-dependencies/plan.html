Automatic input-read dependencies — Backlog plan

Status: Parked backlog · 2026-10-19 · Library-owned

1. Decision context

A computed getter that reads an input only to pick a branch, or to raise, does not depend on that input in the reactive graph. Input values stored in the instance dict have no read hook, so the only way to make such a read a dependency is to wrap the result manually with generate_explainable_object_with_logical_dependency(<input>). Forgetting the wrapper is a recurring error and produces stale values: editing the input no longer invalidates the computed attribute.

Record a dependency edge automatically whenever a ModelingObject input is read while a slot computation is in progress. The invariant becomes "anything read during a computation is a dependency", with no exception to remember, and the wrapper is deleted.

Current wrapper footprint: about twenty call sites (core/hardware/server_base.py, core/hardware/storage.py, the core/hardware/edge/ classes, the EcoLogits builders, builders/hardware/boavizta_server_from_config.py) and three subclass overrides (ExplainableHourlyQuantities, ExplainableRecurrentQuantities, EmptyExplainableObject).

2. Existing groundwork in reactive_core

MechanismState today
Input graph identityEvery input already has a getter-less bump node from _node_slot(container, attr); writes invalidate it through slot_of_attached_value(old_value) in ModelingUpdate.
Relationship readsAlready recorded via record_read_of_node in ListLinkedToModelingObj, ContextualModelingObjectAttribute, the reverse-relationship descriptors and ExplainableObjectDict.
Computed readsAlready recorded as a conservative calculus edge in the computed-attribute descriptor's __get__.
Plain explainable inputsThe gap. Reading self.server_type runs no code at all.

3. Design options

  1. Input descriptor per init parameter (preferred). Install a data descriptor on each class for each get_init_signature_params name, mirroring computed_attribute. __get__ records a calculus edge on the input's bump node when computation_in_progress(); __set__ delegates to the existing __setattr__ logic. Only input reads pay the cost.
  2. ModelingObject.__getattribute__. One method, but it fires on every attribute access including method lookups; the gates in tests/performance_tests/ would likely feel it.

Record the edge as calculus, the kind ancestry already produces for inputs, so graph display stays uniform.

4. Consequences

  • The formula loses its "logically dependent on" nodes, since conditions no longer enter the explainable ancestry. The slot graph keeps them. Accepted: the graph answers "what influences this", the formula answers "how is it computed".
  • Over-recording is harmless by design: a getter that reads an input it then ignores causes a redundant recompute, never a stale value. Bump nodes have no dependencies, so no new cycle is possible.
  • Strengthens the direction of making the slot graph the single persisted dependency graph (see the interface repository's specs/features/calculation-explanations-without-pulls/ discussion).

5. Traps to cover in the plan and tests

  • Reads through a relationship (self.external_api.provider) must land on the target object's descriptor via the contextual proxy's __getattribute__ delegation.
  • EmptyExplainableObject() results that currently get their only parent from the wrapper (for example core/hardware/edge/edge_device.py) must remain constructible with no parent.
  • Reads during validation and invalidation must record nothing, since no computation is on the stack. Add a test so this stays true.
  • Performance gates decide between the two designs if descriptor overhead is visible on the big-system fixtures.
